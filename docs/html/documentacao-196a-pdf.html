1. PRD / Idea

Por que o 196A existe e o que “pronto” significa.

1.1 Problema

A CEMA precisa, todo mês, do relatório 196A — Movimentações por categoria (conta 1.1.1 Taxa de administração) na planilha Google Sheets, para extrair contratos.

O caminho antigo (cookie manual / colar CSV) é frágil. A API app_token / access_token não substitui o 196A. Tokens da API alimentam outro fluxo: Recebimentos / Taxa Adm Realizada.

1.2 Objetivo

  1. Agora (Opção 1): CSV chega na pasta Drive → acionador Sheets preenche 196A* → extração de contratos.
  2. Depois (Opção 2 — pós avaliação): no dia 01, GitHub Actions roda o crawler sem Mac e publica o CSV na mesma pasta Drive.

1.3 Escopo

In scopeOut of scope
Crawler Playwright; relatório 196A (mês anterior, categoria 1.1.1, Detalhado); export CSV + upload Drive; Apps Script import + extrair contratos; agendamento nuvem (planejado, não implementar até GO). Substituir a API oficial de cobranças/repasses; Kubernetes; CompozyOS em produção (só metodologia); reescrita do script analítico.

1.5 Critérios de sucesso

Fase A (atuais)

  • Crawler gera CSV 196A do mês anterior — feito
  • Upload para pasta Drive 196a-automacao-superlogica-controller (Unidade compartilhada) — feito
  • Acionador / menu importa CSV → aba 196A* — feito
  • Sucesso → lixeira; falha → execucoes-com-erro — feito
  • Runbook operacional documentado e validado com o cliente — pendente (T17 / T20)
  • Extração de contratos encadeada ou checklist claro pós-import — pendente (T10)

Fase B (após GO)

  • Dia 01: job roda sem Mac ligado
  • Secrets no GitHub (não no notebook)
  • Alerta se login / OTP / CSV falhar
  • E2E em planilha cópia / staging

3. Decisões (ADRs)

Memória estável. Se a decisão mudar, atualize o ADR antes de mexer no código.

ADR-001 — 196A usa sessão web, não app_token

196A via sessão de browser / CSV. A API de tokens não entrega este relatório.

ADR-002 — PHPSESSID ~3 dias; server-id não autentica

Cookie web é curto. Job mensal deve renovar sessão no dia do uso.

ADR-003 — Preferir CSV → Drive → Sheets (fase 1)

MVP = arquivo CSV na pasta Drive; Apps Script importa. Cookie na planilha é opcional. Contrato: Shared Drive + execucoes-com-erro.

ADR-004 — Download via id de impressão

Baixar o id da run atual (baixar=1 / documentos/download).

ADR-005 — Runtime fora do Mac; não K8s no MVP

Default futuro = GitHub Actions. Só implementar após GO do cliente (ADR-008).

ADR-006 — Pipeline de docs antes de código novo

PRD → TechSpec → Tasks → implementação task a task.

ADR-007 — Separar papéis crawler vs parser vs API

Crawler autentica e publica CSV. Parser importa e extrai contratos. Analítico usa tokens. Não fundir os três.

ADR-008 — Fase B gated por avaliação do cliente

Não implementar GitHub Actions / Docker cron enquanto o cliente não validar a Fase A e der GO explícito. Motivo: Opção 1 já entrega valor; Opção 2 é custo/ops que depende de aceite. Consequência: T7 e T11–T16 ficam blocked até T20.

ADR-009 — Upload Drive via Unidade compartilhada

Pasta de entrada vive em Shared Drive; service account como Gerenciador de conteúdo. Motivo: SA não tem cota no “Meu Drive” (storageQuotaExceeded).

ADR-010 — Dois scripts Apps Script; um onOpen

Planilha carrega analítico + 196A. onOpen só no analítico; chama criarMenuAutomacoes196A_().

4. Operação mensal (visão)

O detalhe passo a passo está no PDF de tarefas.

  1. No Mac: cd integrations/superlogica-crawler e PLAYWRIGHT_HEADED=true npm run crawl
  2. Confirmar CSV em output/ e upload na pasta Shared Drive
  3. Esperar o acionador (15 min) ou importar pelo menu Automações Privadas
  4. Conferir aba 196A*
  5. Rodar Extrair Contratos e validar a aba destino
  6. Se o CSV foi para execucoes-com-erro, não extrair — investigar o arquivo
Fazer agora: T18 → T17 → T19 → T10 → T20. Fase B só depois do GO.
