T18

Garantir dois .gs no Apps Script e os dois menus

Dependências: T8 (done).

Passos

  1. Abrir a planilha de produção e Extensões → Apps Script.
  2. Confirmar que existem dois arquivos: superlogica-cobrancas-analitico.gs e extracao-contratos-196a.gs.
  3. No analítico, manter o único onOpen. Ele deve chamar também criarMenuAutomacoes196A_().
  4. No arquivo 196A, não deixar um segundo onOpen. Se existir, remover ou comentar.
  5. Salvar, fechar a planilha, reabrir. Autorizar Drive + Sheets se o Google pedir.
  6. Conferir a barra de menus: Superlógica Analítico e Automações Privadas.

  8. Smoke test 2: Automações Privadas → importar CSV Drive (ou “Instalar acionador Drive 15 min” se ainda não existir).
Aceite: os dois menus visíveis; Importar por período e Importar CSV Drive funcionam; um único onOpen.

T17

Runbook operacional Fase A (mensal)

todo · ops · S

Por quê. A Opção 1 já roda, mas o cliente precisa de um checklist único: o que clicar, o que conferir e o que fazer quando o CSV cai na pasta de erro.

Dependências: T5, T8 (done). Dono: operação CEMA + docs.

Passos — escrever e validar o runbook

  1. Criar (ou atualizar) um checklist de uma página com os passos abaixo. Pode viver no README do crawler + Sheets e neste PDF.
  2. Validar o checklist com uma execução real do mês vigente (ou do mês anterior, se for o ciclo).
  3. Incluir o caminho de erro: CSV em execucoes-com-erro → não extrair contratos → abrir o arquivo → anotar o motivo → recolocar CSV corrigido na pasta raiz.
  4. Definir quem executa no Mac e quem confere a planilha.

Checklist mensal (conteúdo do runbook)

  1. No Mac, pasta integrations/superlogica-crawler. Conferir .env com DRIVE_UPLOAD=true e DRIVE_FOLDER_ID.
  2. Rodar PLAYWRIGHT_HEADED=true npm run crawl. Completar MFA se a sessão .auth/storage-state.json tiver expirado.
  3. Conferir: CSV em output/ e o mesmo arquivo na pasta Shared Drive 196a-automacao-superlogica-controller.
  4. Não converter o CSV em Planilha Google.
  5. Esperar até 15 minutos o acionador — ou usar o menu Automações Privadas → importar agora.
  6. Abrir a aba cujo nome começa com 196A. Conferir linhas, competência (mês anterior) e categoria 1.1.1.
  7. Se a aba preencheu e o CSV sumiu da pasta (foi para a lixeira): import ok. Seguir T10 (extrair contratos).
  8. Se o arquivo foi para execucoes-com-erro: parar. A aba não deve ter mudado. Investigar encoding, cabeçalho ou arquivo vazio.
  9. Registrar data, operador e “ok / erro” numa linha de log (planilha ou doc interno).
Aceite: checklist crawl → upload → acionador → conferir 196A* → extrair; inclui o que fazer se o CSV for para execucoes-com-erro.

T19

Checklist de segredos locais

todo · ops · S

Por quê. Sessão, OTP e service account não podem ir para o git. Se vazar, precisa haver rotação documentada.

Dependências: T5 (done).

Passos

  1. Abrir .gitignore na raiz e no crawler. Confirmar .env, .auth/, google-sa.json, storage-state.json.
  2. Rodar git status e git ls-files filtrando .env, sa.json, storage-state. Nada disso pode estar versionado.
  3. Confirmar que a cópia operacional da service account está só em integrations/superlogica-crawler/.auth/google-sa.json (ou o caminho do GOOGLE_APPLICATION_CREDENTIALS).
  4. Anotar o procedimento de rotação: nova senha Superlógica; novo app password / IMAP se o OTP mudar; nova chave da service account no Google Cloud + substituir o JSON; revogar a chave antiga.
  5. Se algum segredo já foi commitado no passado, tratar como vazamento: rotacionar e limpar o histórico só com autorização explícita.
Aceite: nenhum segredo no git; .auth/ e .env no .gitignore; rotação documentada.

T10

Encadear ou documentar Extrair Contratos após o import

todo · sheets · S

Por quê. O import enche 196A*, mas o valor de negócio é a aba de contratos. Hoje o operador pode não saber o próximo clique.

Dependências: T8 (done).

Passos (escolher um caminho e fechar)

  1. Abrir extracao-contratos-196a.gs e localizar a função de extrair contratos e o nome da aba destino.
  2. Decidir: (A) só documentar no runbook T17 o clique manual no menu, ou (B) chamar a extração automaticamente no fim do import bem-sucedido.
  3. Se A: escrever no runbook “após import ok, menu Automações Privadas → Extrair Contratos” e qual aba conferir.
  4. Se B: no sucesso do import Drive, enfileirar a extração; não extrair se o arquivo foi para execucoes-com-erro.
  5. Testar com um CSV conhecido: import → extração → conferir quantidade de contratos e competência.
  6. Anotar no runbook o que fazer se a extração vier vazia (aba 196A sem detalhe, filtro errado, cabeçalho diferente).
Aceite: depois do import ok, o operador sabe (ou o script enfileira) rodar Extrair Contratos na aba destino, sem dúvida.

T20

Validação com o cliente — Fase A ok para uso mensal?

todo · verify · S

Por quê. Porta de decisão da Fase B. Sem isto, GitHub Actions não começa.

Dependências: T17, T18 (e na prática T10 + T19).

Passos — reunião / aceite

  1. Agendar 30–45 min com o financeiro CEMA. Levar o runbook T17 e a planilha com 196A* do último ciclo.
  2. Demonstrar ponta a ponta: crawl (ou CSV já na pasta) → import → aba 196A → extrair contratos.
  3. Perguntar: a Opção 1 serve para o fechamento mensal, mesmo com o Mac só no dia do crawl?
  4. Registrar por escrito uma das três saídas:
    • GO Fase B — automatizar dia 01 no GitHub Actions.
    • NÃO-GO / depois — continuar Fase A; Fase B permanece blocked.
    • Ajustes — listar o que falta na Fase A antes de novo T20.
  5. Se GO: decidir canal de alerta (e-mail CEMA ou Telegram) — pendência da documentação.
  6. Atualizar o ADR-008 e o status das tasks T7 / T11–T16 (sair de blocked só com GO).
Aceite: cliente confirma operação da Opção 1; decisão GO / NÃO-GO para Fase B registrada.
Sem GO, não criar workflow, Dockerfile de cron, nem secrets no GitHub.
